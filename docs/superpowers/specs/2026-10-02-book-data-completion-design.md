# 书架批量数据补全设计

## 目标

在书架批量处理区域增加一个“数据补全”操作，用于重新读取选中书籍的正文文件，补回缺失的封面和书籍元数据。该操作不替代现有的一次性旧数据恢复机制。

## 行为边界

- 只处理当前选中的书籍。
- PDF 重新渲染第一页作为封面；EPUB、MOBI、AZW3 重新提取内置封面和元数据。
- 只填充空字段，不覆盖用户已有内容。
- 封面字段已有值时不覆盖；标题、作者及 `meta` 中已有字段也不覆盖。
- 不修改标签、分组、评分、状态、阅读进度、阅读位置和批注。
- 无法读取正文或解析失败的书籍单独计为失败，不中断整批处理。
- 处理完成后刷新书架并显示成功、跳过、失败统计。
- 批量解析串行执行，避免同时占用多个解析器或 PDF 渲染器。

## 数据流程

1. 读取选中书籍的完整记录。
2. 根据 `book.path` 加载正文文件；远程/仅在线路径无法读取时计为失败。
3. 调用现有格式解析器获取候选元数据和封面。
4. 将候选值与现有记录合并：现有非空字段优先，候选值只补空字段。
5. 保存新封面到托管封面目录，并写入书籍记录。
6. 汇总结果并刷新书架。

## UI

批量操作区增加单个按钮：`数据补全`。按钮仅在有选中书籍时可用，执行期间禁用重复触发。完成提示包含成功、跳过和失败数量。

## 复用与日志

复用现有 `loadBookFile`、EPUB/MOBI/PDF 元数据解析和 `saveCoverFile` 流程；不新增第二套日志系统。批量操作仅通过现有 `diagnosticLog` 记录开始、单本失败和完成摘要。

## 验证

- 单元测试覆盖空字段合并、已有字段保留、不同格式解析失败隔离和批量统计。
- 运行完整测试套件和生产构建。
